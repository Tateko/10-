# これまでにつまずいた所と、直し方（1〜4本目で分かったこと）

## 環境（クラウド・Linux）
- キットの setup_mac.sh は Mac 以外で止まる → `scripts/setup_cloud.sh` を使う。
- キットはフォントを Mac／Windows の場所でしか探さない → `~/Library/Fonts` にも Noto Sans JP を置く（setup_cloud.sh がやる）。
- 無料の声（Mac の say）が無い → `~/.local/bin/say`（OpenJTalk）で代わりをする。Mac の Kyoko とは声が違う。
- `playwright install` はしない。この環境の Chromium（/opt/pw-browsers）に合う版の Playwright を入れる（setup_cloud.sh がやる）。
- github.com・YouTube・多くの記事・画像生成サービスの画像置き場（cloudfront など）は止められている。ページは Chrome の Claude に読んでもらう。Higgsfield などで作った画像は取り込めないので、図と動くイラストはここで描く（make_visuals.py）。
- この環境は時間がたつと消える。完成した動画・サムネ・説明欄は、本人にダウンロードしてもらう。

## 図・動くイラスト
- HTML の文字で、数字だけ明朝のような別の字形になることがある → font-family に `sans-serif` を足し、600ms 待ってから撮る（common.py でやっている）。
- 動くイラストを続けて撮ると、前のページの `window.__tick` が残って止まる → 毎回 about:blank に戻す（common.py でやっている）。
- 図の中身が小さいと、動画の中で小さく見える（キットは 1600×740 の枠に収める）→ zoom で中身を大きく描く。
- 冒頭の予告に使うクリップは、文が短い（2〜3秒）。`"start": 秒` で途中から再生して、結末（数字が出る所）を見せる。
- キットの一覧画像（contact_sheet）は、動くクリップの最初のコマを出すので空に見える。finish.py の check_clips.jpg（途中のコマ）で確かめる。
- 動くクリップがナレーションより短いと、最後が止まった画面になる。visuals.json の seconds は「そのシーンの文の数 × 4秒」を目安に長めにとる（1回書き出したら、キットの check_report の「クリップが短い」を見て seconds を足す）。
- anim_line の to・from は短く（6字まで）。長いと折り返して線と重なる。
- 長い文字のハンコ・サムネの大きな数字は、道具が字数で大きさを決める（はみ出したら文字を短くする）。

## 台本の書き方
- 出典の番号は [1] のような数字で書く。[X25] のような文字入りでも build_plan は読み上げから外すが、キットのチェックが「plan に入っていない文」と数えてしまう。

## 書き出しと仕上げ
- キットのチェックで「最大の音が −1 dBFS より上（割れるおそれ）」がよく出る → finish.py が limiter で下げる。
- 概要欄の下書きは、最初の章が 0:00 になる（冒頭が章ではないため）→ finish.py が「0:00 冒頭」と本当の第1章の時間に直す。
- 説明欄は短く（全角を2字と数えて 4,500 まで）。出典は記事ごとでなくサイトごとにまとめる。
- 書き出しは10分前後かかる → バックグラウンドで実行し、終わったら知らせる。

## 中身
- 本人の記事どうしで数字や月が食い違うことが多い。台本では片方だけを使うか、「辞めて◯か月目」のように食い違わない言い方にする。事実メモの「台本に入れないこと」に理由を書く。
- 記事に通貨が書かれていないときは、円にしない（P3 で確かめる）。
- 日本語で同じ話がすでに紹介されている人（例：Andon Market の Luna・Pieter Levels・Marc Lou）は選ばない。
- 毎月の定期の売上（MRR）と、月の売上全体は別の数字。題名・サムネで並べて比べない。

## 4本を見直して分かったこと（2026/10/31）
- 題名の大事な所が一覧で切れていた → 強い数字と結末を最初の20字に（finish.py が確かめる）。
- 「5,989から、40,451へ」のように単位がなかった／回ごとに円にしたり、しなかったりした → 毎回「元の通貨＋約◯万円」。
- お金の話のサムネ3本が、同じ暗い緑・数字4行で見分けられなかった → hero 型（文字2行・数字1つ・影絵・回ごとの色）。
- 個人開発者の話3本に有名企業の創業物語が混ざり、軸が分かれた → 最初の10本ほどは軸を1つに（判定 G）。
- 章の名前の読点（「初めての、給料」）が不自然 → 読点なし（build_plan.py が警告する）。
- ショートがなかった → 毎回 make_short.py で1本。
