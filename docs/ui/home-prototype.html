これまで

表紙をえらぶ

選んだ色は、あなたの画面ぜんぶに広がります。

表紙はあなただけのものです。ほかのメンバーの画面は変わりません。

さわってみてください

  • 01「行く」を押す — 相手が誰かは出ません。出るのは時刻と場所と、相手の表紙の色だけです。
  • 02表紙をかえる — 右上のボタンから6つの表紙と、自分の写真。色はカードの縁、タグ、ボタンまで連動します。
  • 03だれの画面を見るか切りかえる — 下のボタンから。ひとりひとりが別の表紙と、別の提案を持っています。

だれの画面を見る?

これはプロトタイプ用の操作です。実際のアプリに、ほかの人の画面を見る機能はありません。

名前より先に、色で人を認識する。
改札で探すのは名前ではなく「藤色の表紙の人」です。表紙は設定画面の飾りではなく、当日あなたを見つけるための名札になります。表紙のカスタマイズと人間関係は、別々の機能ではなく同じひとつの仕組みです。

10年後、人はどう出会っているか

  • 01選べない — 「この人と会う」というボタンはありません。あるのは「行く」だけ。選べる範囲は、自分が気づいている範囲でしかないからです。
  • 02人ではなく体験に集まる — 提案されるのは必ず体験です。人は「ほかに2人に届いています」としてしか現れません。
  • 03会う前に話さない — メッセージ機能を作りません。会う前にテキストで擦り合わせると、会う前に関係が終わります。
  • 04その日で解散していい — 「また会う」ボタンも友だちリストもありません。続きは、アプリの外で起きるべきです。

明るい未来を、暗い画面に光る線で描かないことにしました。このアプリが開かれるのは毎朝7時です。だから基調は朝の光――白に近い地色、すりガラス、ゆっくり動く大気。見出しだけを明朝にして、提案文が「システムの出力」ではなく誰かの言葉に見えるようにしています。

未解決: 初対面で会う以上、安全の設計が要ります。いまは「合流は3人から」「公共の場所だけ」を前提に置いていますが、これだけでは足りません。docs/relationships-2036.md に残りの宿題を書いています。

implementation

実装するときの決めごと

表紙の持ち方

users.cover_theme（プリセット名）と users.cover_image_url（写真）の2列だけ。プリセットは文字列なので、あとから増やしてもマイグレーション不要です。

色の連動

表紙が決めるのは --c1 --c2 --c3 --accent --accent-deep の5つ。個々の部品に色を直接書かず、必ずこの変数を経由させます。表紙を足すときCSSは1行です。

読めることを壊さない

文字色は表紙に関わらず #12151C 固定。表紙はすべて明度の高い色に限定し、写真のときだけ下半分に白のスクリムを敷きます。

作らないもの

チャット、友だちリスト、「また会う」ボタン、相手の検索、プロフィール閲覧、1対1のマッチング。機能を足したくなったら毎回ここに戻ります。

合流の単位は3人

1対1にしません。抜けても相手がひとりにならないので断りやすく、沈黙が事故にならず、初対面が1対1で会う状況を作らずに済みます。押した人が1人なら、ひとりで行く。それも失敗ではありません。

表紙は識別子でもある

cover_theme は当日の目印として同行者にも見えます。顔写真と名前の代わりに色を出す、という設計です。同じ色がかぶったときの扱いは未決。

触れる場所を絞る

ホームで押せるのは「表紙」と「3つのボタン」だけ。判断の回数を増やさないという方針を、画面の要素数で守ります。
