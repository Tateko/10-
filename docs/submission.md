## 1. 誰の、どんな困りごとを、どう変える作品ですか？

「今日なにをするか」を決めるのが面倒で、結局いつものカフェと動画で休日が終わる人が対象です。検索もレコメンドも「あなたが好きそうなもの」しか返さないので、放っておくと世界は狭くなり続けます。michi は逆向きに、その人が書いた「いつもの過ごし方」から**選ばない領域**を推定し、今日この時間・この予算で実行できる体験を3つ、**なぜあなたはこれを選ばないか**・誘う相手・そのまま送れる誘い文・60秒でできる最初の一歩まで揃えて出します。

## 2. 「10年後のあたりまえ」と、どうつながりますか？

調べる・手配する・最適化するをAIが全部やる世界では、人に残る希少資源は「予想外に出会うこと」になります。10年後は、AIが自分より自分の傾向を知っていて、毎朝「今日の未知」が1件だけ届き、判断ゼロで人に会いに出るのがあたりまえになっている、という姿を想像しています。

**今回できたのは**その中核、「傾向の外側を生成して、今日の行動に落とす」ところまでです。通知配信・行動ログやカレンダーからの入力自動化・提案の先で人をマッチングする部分は**今回未実装の構想**です。

## 3. まず、どこを見ればよいですか？

1. **設定タブ**に呼び名と「いつもの過ごし方」を入れる。例:「休日はだいたい家で動画。外に出るときは決まったカフェ。人と会うのは月1回くらい。」（ここが提案の根拠になります）
2. **ホーム**でエリア「渋谷」／時間「1時間」／気分「刺激がほしい」を選び、**今日の未知を出す**。→ 3案が出ます。**まず読んでほしいのは各案の「なぜ、あなたはこれを選ばないか」**。設定に書いた本人の言葉を引用して根拠が書かれます。右上の「未知度」ゲージが、その案が普段からどれだけ離れているかです。
3. **「これにする」を長押し**して確定。ここが本作の肝です。確定した瞬間にアプリ全体がロック画面に変わり、**完了を報告するまで他のタブに戻れません**（離脱も「やめる」の3秒長押しだけ）。「完了を報告する」→ 写真か一言 →「完了にする」で、朱色の「未知」の印が捺された完了画面になります。

体験として見るべき1つは **3 の「決めたら戻れない」** です。提案を読ませることではなく、動かすことを目的にした設計です。

## 5. 今回作った部分と、独自の工夫

今回ゼロから作ったのは、サーバー（Express + Anthropic SDK の構造化出力）、プロンプトの制約設計、画面のすべて（HTML1ファイル・フロントの依存ライブラリ0）、そして配色・書体・モチーフを含むデザインシステムです。既存を使ったのは Claude API / Express / Zod / Webフォントだけで、UIフレームワークもテンプレートも使っていません。

工夫は3点です。(1) **Zodスキーマで「3案・12項目」を型として強制**し、生成のブレでUIが壊れない構造にしたこと。(2) **決めたら戻れないロック**（確定は長押し、離脱も3秒長押し）で、判断を1回に閉じ、決めた後に別の案やSNSへ逃げる余地を消したこと。(3) 「AIが作った感じ」を消すため、墨・生成紙・**朱**の3色（黒＝進む／朱＝確定・不可逆と役割を固定）、明朝の見出し、紙のグレイン、「道」の一本線だけでUIを組み、グラデーション・グラスモーフィズム・絵文字アイコンを一切使わなかったこと。

## 6. AIを何に使い、どのように役立ちましたか？

**作品内**: `claude-opus-5` が「傾向推定 → 傾向の外側の生成 → 行動化（誘い文・最初の一歩）」を一度に担います。構造化出力（Zod スキーマ）で毎回同じ12項目が返るため、生成物をそのままUI部品として扱えます。AIを文章生成ではなく**判断の代替**に使っている点が中心です。

**制作中**: 実装は Claude Code、画面検証は Playwright で全画面を自動スクリーンショットして人間の目で詰めました。

**人間が決めたこと**: 「選ばない理由を必ず言う／定番・無難は禁止／3案中1案は必ず人を誘う／断定できない固有名詞は出さない」という**禁止則の設計**、ロックというUXの発明、色・書体・モチーフの選択です。AIは書き手で、**何を書かせないかを決めたのが我々**です。
